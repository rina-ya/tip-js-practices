| 1 | Отсутствующий элемент — `null`; пустая коллекция — длина 0 | Совпало: `null` и `0` | `querySelector` без совпадений даёт `null`, `querySelectorAll` — пустой NodeList |

| 3 | Старый NodeList не меняется, новый растёт | Совпало: старое значение 1, новое 2 и 3 | `querySelectorAll` возвращает статический снимок |

**Итог по эксперименту 5.** Нажатие на вложенный `span` даёт `event.target = span`, а `currentTarget` на каждом шаге — тот элемент, чей обработчик сейчас работает. Поэтому `closest` важен: он позволяет найти кнопку от исходной цели события.

## 9. Расширение Б. Однократная отмена последнего удаления

Реализовано в `src/task-extra.js`.

Правила поведения:

- После удаления запоминается сама задача и её позиция в массиве.
- Кнопка «Отменить удаление» становится активной.
- Отмена возвращает задачу на прежнюю позицию с исходным статусом и приоритетом.
- После отмены кнопка снова недоступна.
- Новое удаление заменяет предыдущую возможность отмены.
- Изменения статусов других задач отменой не затрагиваются.
- Восстановление не изменяет входной массив.

## 10. Отладка

Остановка на строке чтения `dataset.taskId` в `handleTaskListClick` показывает:

- `card.dataset.taskId` — строка `"4"`;
- после `Number(card.dataset.taskId)` — число `4`;
- `Number.isSafeInteger(id)` возвращает `true`;
- `findTaskById(currentTasks, id)` возвращает объект задачи с этим id.

Дальше `setTaskCompleted` или `removeTask` возвращает `{ ok: true, tasks: [...] }`, массив `currentTasks` обновляется, `renderApp()` перерисовывает карточки, `restoreTaskFocus` возвращает фокус на кнопку той же задачи.

Проверка граничных случаев:

- изменение `data-task-id` на `"777"` — операция отклоняется, сообщение «Задача не найдена»;
- изменение на `"4abc"` — `Number("4abc")` даёт `NaN`, проверка `isSafeInteger` не проходит, сообщение «Некорректный идентификатор задачи».
