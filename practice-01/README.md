1. Открыть `practice-01/index.html`.

## Задание 1. Различие результатов в двух средах

| Среда | Вывод | `typeof document` | Причина различия |
|---|---|---|---|
| Node.js | Текст о студенте и практической работе | `undefined` | В Node.js нет DOM — объект `document` не определён |
| Браузер | Тот же текст (если скрипт подключён к HTML) | `object` | Браузер предоставляет DOM через глобальный объект `document` |

**Вывод:** один и тот же JS-код выполняется в разных средах по-разному, потому что Node.js — серверная среда без DOM, а браузер — клиентская с DOM.

## Отладка (`debug.js`)

### Исходный вывод программы

```
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

### Исправленный вывод

```
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

### Причины ошибок

| Ошибка | Что наблюдалось | Причина | Исправление |
|---|---|---|---|
| Обработка количества задач | `completedTotal = "32"`, `remainingTasks = -24` | Оператор `+` для строк выполняет конкатенацию `"3" + "2" = "32"`; затем `"8" - "32" = -24` | Обернул в `Number()`: `Number(completedText) + Number(additionalText)` |
| Граница цикла | `controlSum = 6` вместо 10 | Условие `taskNumber < 4` завершает цикл на 3, не включая 4 | Заменил на `taskNumber <= 4` |

### Точка останова

Иллюстрация: `screenshots/debug-breakpoint.png` — на скриншоте видна остановка на строке `const completedTotal = ...`, панель **Scope** с переменными `completedText = "3"` (тип `string`), `additionalText = "2"` (тип `string`).

## Вывод

В ходе работы освоены: запуск JS в Node.js и браузере, различие сред, приведение типов, условные конструкции, циклы `while` и `for`, работа с DevTools (точки останова, пошаговое выполнение, панель Scope), оформление отчёта в Markdown и базовая работа с Git.

Наиболее показательной оказалась ошибка в задании 5: строки `"3"` и `"2"` при сложении дают `"32"` — это демонстрирует, что JS не преобразует типы автоматически при `+`, и без явного `Number()` вычисления дают бессмысленный результат. Это особенно опасно, потому что исключения не возникает — программа «работает», но считает неправильно.

При выполнении расширения (Вариант Б) дополнительно освоены: моделирование календарных дней, обработка выходных в цикле `while` и подсчёт двух независимых счётчиков (рабочих и календарных дней).
